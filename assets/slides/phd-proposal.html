Why Verification Does Not Scale

n ReLUs: 2n subproblems
Deep models: abstraction exceeds memory
Too many subproblems, and computing abstraction for each is too expensive.
Why does verification not scale? Two reasons. First, the tree: in the worst case every abstraction is too loose, so every ReLU must be split. Three split ReLUs give 8 subproblems, n give 2 to the n. Verification is NP-complete. Second, computing abstraction is computationally expensive: each subproblem computes it through the whole network. For a small CNN that fits in GPU memory, but for a 110-layer ResNet or GPT-2 Medium, existing verifiers run out of memory computing a single abstraction. Too many subproblems, and computing abstraction for each is too expensive. This is the scalability challenge.

Tackling the Exponential Search TreePart I · Scalability

Rsb learns which neuron to split first.
NeuralSAT learns from conflicts; VeriStable stabilizes neurons.

Part I tackles the exponential search tree in three ways. First, prune it: NeuralSAT learns clauses from conflicts, and VeriStable finds neurons whose sign is already fixed, so whole subtrees disappear. Second, branch smarter: Rsb learns which neuron to split next, and explores half as many branches. Third, compute abstraction at scale: every node computes abstraction through the whole network, and for deep networks and transformers that exhausts GPU memory. CoVeNN computes abstraction for a 110-layer ResNet.

We turn structural robustness (SR) into local robustness (LR).
Scaling, blur and echo are structured perturbations. They couple input elements, so verifiers cannot encode them as intervals. VeriS encodes the structural perturbation as layers prepended to the DNN. How much of it is applied becomes a few parameters in intervals. The result is an LR problem that existing verifiers solve. They solve 78 percent of 5,508 structural robustness problems they could not encode before. VeriS fixes the kernel, for example blur at one angle. VeriDou turns the kernel entries themselves into variables in intervals, so one property covers every kernel in a range, every angle at once, plus independent pixel noise. It is still an LR problem for existing verifiers. On CIFAR-100, at the same perceptual budget, noise alone finds no counterexamples, predefined kernels find 39 percent, every kernel finds 70 percent, and every kernel plus noise finds 99 percent. Across networks, dual perturbations find counterexamples in up to 99 percent of cases.

ZonoGPT keeps the block-by-block abstraction, so memory still fits. The change is what passes between blocks: a zonotope instead of an interval. A zonotope is a center plus a few directions, each scaled between minus one and one, so one direction moves several features together and their relations are kept. To keep memory fixed, after each block ZonoGPT keeps only the m largest directions and folds the rest into a small box. Inside a block, it computes abstraction for the whole LayerNorm with one fused transform, and the whole attention, with its skip connection, with another; CoVeNN instead computes abstraction for each operation, mean, variance, divide, QK-transpose, softmax, PV, on its own.

Lagrangian relaxation: tighter abstraction.
CLAD is an abstract domain that carries the input constraints themselves through the network. It relaxes each constraint into the objective with a Lagrange multiplier. It never computes abstraction over infeasible inputs, so the over-approximation stays on the safe side and the property is verified. It verifies about 60 percent more l2-ball instances than GCP-CROWN, and 3.3 times as many on the largest network. On plain l-infinity properties it matches GCP-CROWN. Submitted to ICLR'27.

Quantized parameters live in memory, and Rowhammer or radiation can flip their bits. Real attacks flip several bits, but BFAVerifier handles only one flipped parameter. A one-flip proof gives false assurance: only 61 percent of those instances stay verified with four flips. Enumerating combinations is infeasible, and exact MILP does not scale.

mBFV: Multi-Parameter Bit FlipsICLR'27 · submitted

Key idea: sum the m largest contributions.

Bound propagation gives one contribution per flipped parameter. With at most m flips, the worst case is the sum of the m largest contributions, so mBFV never enumerates combinations. BaB over flip locations tightens the abstraction, with polynomially many subproblems. It verifies 293 of 625 instances, against 38 for BFAVerifier and none for exact MILP, on networks up to 1.15 million parameters.
